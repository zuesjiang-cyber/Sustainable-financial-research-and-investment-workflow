# FinTrust：持续更新的投研状态

复用现有 React + Express + SQL.js + Decimal 项目，将“初始观点 → 新材料 → 证据与计算 → 观点变化 → 人工确认 → 下一轮记忆”接成一条流程。

## 启动

需要 Node.js 22 或更新版本。

```bash
npm ci
cp .env.example .env
npm run dev
```

打开终端输出的地址，默认 http://127.0.0.1:3000 。也可以直接 `FINTRUST_DATA_DIR=./data-local npm run dev`，先体验不调用模型的人工复核流程。真实研报上传的本地文件、解析 manifest、证据片段和回执默认写入 `./uploads`；建议在 `.env` 中用 `FINTRUST_UPLOAD_STORAGE_DIR=./uploads-local` 指定私有目录（不会写入研究数据库）。

## 本轮 P0

- 新建公司研究项目，保存初始观点、验证条件、理由和待解问题。
- 粘贴新资料，服务器生成文档与逐字原文片段；文字输入标注行号，不伪造 PDF 页码。
- 有模型配置时：单个 Research Agent 调用项目内搜索、文档阅读、确定性财务计算，然后产出草稿；展示工具记录、主张核验和观点变化。
- 原文披露、计算结果和待验证的解释分开呈现。没有足够新证据时，保留上轮已确认状态，标注本轮尚未解决。
- 用户修改状态、理由、修正与后续问题后确认；原模型草稿与最终确认结果分别留存。
- 下一轮读取当前观点、分析师修正、验证标准、历史回答。修正不被“同意本轮”的模板文本覆盖。
- 草稿绑定材料及研究状态；过期结果不能覆盖新状态。重复保存同一内容只生效一次。
- SQLite 保存、快照导出导入；测试使用隔离临时数据库，不改你的研究数据。

## 模型与输入

当前指定核心模型为 **Ling-3.0-flash-Fin**，沿用 OpenRouter 接口。将 `.env.example` 复制为 `.env`（已有 `.env` 时直接编辑，不覆盖），在本地填写 `FINTRUST_LLM_API_KEY`；接口和模型 ID 已填在示例中。密钥只由服务端读取，`.env` 不进入 Git。旧 Gemini 接入仍保留，但不作为本轮 Ling 验收的替代。

先独立验证模型连接，再开发研报业务：

```bash
npm run model:check
npm run model:check -- --tools
```

第一条验证实际模型文本回复；第二条验证合成工具调用及结果回传。检查会真实发送小型合成输入，消耗服务商额度，不上传用户研报。缺 Key 或请求失败时非零退出，不返回样例成功结果。离线自动测试不调用真实模型，不能代替上述真实连接验收。

用户已调整需求：财报由用户上传，暂不自动查找最新财报；需求第 4 项暂缓；先接通真实 API，再处理上传及观点、核验和持续记忆。当前执行范围见 [API 接入记录](docs/product-architecture-v1/reviews/2026-09-04_API接入与当前范围.md)。模型连通检查不表示新研报页面及全部产品功能已接通。

报告首页的正常上传入口会将用户选择的 PDF 通过 `POST /v1/uploads` 发送到服务端，校验类型/大小后保存原始字节并运行现有 PDF parser，返回文件 hash、页数和解析片段数。该阶段不会识别公司、提炼观点或自动查找财报；成功回执会明确提示观点提炼尚未运行。页面下方的固定圣邦/汇顶按钮仍是单独标注的本地样例演示，不能作为真实上传结果。文本材料入口仍可提供标题、正文和已知披露日期；不确定的披露日期留空。

确认前草稿暂存在服务端内存，保留一小时；重启后未确认草稿需要重新分析。已确认的研究状态与历史保存在数据库中。

## 验证与构建

```bash
npm run lint
npm test
npm run build
NODE_ENV=production npm start
```

验收主线：新建 T0 → T1 分析并写入用户修正 → T2 提供新资料 → 核查旧修正仍在 → 导出/导入与重启恢复。另测错误引用、计算单位与边界、过期草稿、重复确认、失败保存。
