# 07 研究状态与 Memory

## 1. Memory 存的是什么

Memory 是可追溯的公司研究状态，不是把聊天记录无限追加到提示词。它由原始观点、已确认的当前判断、历次变化、用户修正和未解问题构成。

四个对象明确分离：

- `Thesis`：长期观点身份；
- `ThesisRevision`：这条观点当时具体是什么意思、目标和标准是什么；
- `ThesisAssessment`：某次新证据对该观点的核验结果；
- `UserJudgment`：使用者认可或补充的当前理解。

新证据改变 assessment；观点自身被用户修订才产生 revision。论文式摘要和“模型记忆文字”都不作为独立事实源。

## 2. 状态构成

`ResearchState(version)` 包含 active thesis revisions、最新已确认 assessments、用户判断、未解/已解 questions、source coverage、research method preference、last update ID。

项目表只保存 `currentVersion` 指针。每次确认写不可变 update 和 snapshot；当前页从指针读快照。snapshot 是读取优化，不是另一套允许单独修改的事实系统。

历史事实存在 facts/calculations/evidence 中，由 state 中的 IDs 引用。导出时同时带引用清单，避免只剩一段无法追根的总结。

## 3. 第一次与第二次

第一次：研报原始观点 → 提取 revision 1 → 与最新披露核验 → 用户确认 → state v1。原始观点的出处和提出日期始终保留。

第二次：读取 v1 → 新财报事实 → 相同 thesis IDs 的新 assessment → 草稿与 v1 diff → 确认 v2。v1 不变化；v2 能指明哪些新材料使判断变化。

例：原研报看好高端化与全年毛利率。第一期只有毛利率改善、没有产品结构披露：数值阶段信号改善、因果仍待验证。第二期财报给出产品占比和管理层解释：产品结构观点获得新支持，但独立因果证明强度仍如实表述。用户不需要重新建立项目和观点。

## 4. 用户修正怎样生效

修正有类型和作用域：

| 类型 | 生效范围 |
|---|---|
| THESIS_TEXT | 指定 thesis 的后续 revision，保留原研报原句 |
| CRITERION | 指定核验条件，重跑受影响 assessment |
| USER_JUDGMENT | 用户当前观点，不冒充系统得出的状态 |
| RESEARCH_PREFERENCE | 该项目关注重点和表述偏好 |

每条记录包含 set/clear、原值、新值、原因、作者、时间、基准版本。清除修正也是新事件。模型不得因上下文裁剪而忽略有效修正；context compiler 必须把生效的修正列入最高优先级。

## 5. 上下文编译顺序

按以下顺序装配，不先拼一个长故事再希望模型记住：

1. 当前项目、主体、asOf、会计与合并口径；
2. 有效用户修正与核验标准；
3. 本轮涉及的原始观点和当前 revision；
4. 上次已确认 assessment、关键事实和用户判断；
5. 与本轮相关的未解问题及最近变化；
6. 相关历史片段的按需摘要。

每个项含 origin/version/source IDs。上下文预算初值 12k tokens，先确保前 3 项；历史过多按观点分批，而不是截断用户修正。历史摘要可以重新生成，不能替代原事件。编译产物及输入 hash 存 run checkpoint，便于解释本轮用了什么记忆。

## 6. Skill 的最小实现

V1 将“项目研究方法”实现为一个版本化 JSON 配置：重点指标、行业术语别名、重点问题、比较口径与输出偏好。项目可自动从已确认研究中建议更新，由用户保存。

它影响计划和检索，不改变财务事实，不允许运行用户上传脚本。暂不建设插件市场、技能编辑器和跨项目自动学习平台；当前产品所需的“越用越懂这个项目”由结构化 Memory 与少量方法配置实现。

## 7. 观点生命周期

ACTIVE 继续追踪；ARCHIVED 暂不核验但历史可读。预测目标到期后保留最终 assessment，用户可选择创建下一期目标 revision；系统可以提出建议，不能把旧预测无声滚成新预测。

观点分拆或合并记录 `derivedFromThesisIds`，新旧 ID 关系可追溯。与另一家公司相似的观点不跨项目直接复用判断。

## 8. 问题的生命周期

问题包含关联 thesis、提出原因、期待证据、触发期间、状态 OPEN/ANSWERED/DEFERRED、回答和引用。新财报到来先检查旧问题是否获得答案；确认后写问题变更。系统不得只不断增加问题而不处理旧问题。

同一问题按关联观点+归一化内容去重，模型可建议合并；历史原问句保留在 update。用户手动延期或修改的问题在后续 context 中保留。

## 9. 记忆正确性的验收

必须用真实两轮材料证明：同一观点 ID 不漂移；原研报观点未被改写；用户修正被第二轮使用；旧问题被回答或明确继续开放；历史快照可复现；新事实不回写过去的 asOf 状态。参见 [12 验收](12_验收与评测.md)。
