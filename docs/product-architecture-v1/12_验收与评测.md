# 12 验收与评测

## 1. 最终验收场景

操作者上传一份此前未跑过的真实研报 PDF，系统自行拆观点、定位公司、找到截至当前的最新正式财报、抽事实并完成逐条核验。操作者能点引用回原页，修改一个观点标准，保存研究。随后输入下一期财报或推进受控历史 asOf，再更新一次：同一观点 ID 保留、先前修正生效、旧问题被处理、v1/v2 可回看。整个过程在页面刷新和一次 Worker 重启后仍成立。

演示回放可以证明布局，不能替代该场景。项目中已有单元测试通过也不自动证明 PDF 与自动获取链路完成。

## 2. 评测资料集

最低：3 家沪深公司、每家 1 份有可核验观点的研报 + 2 个相继披露期的官方完整财报，必要时补比较年报。至少 1 份常见扫描/混合 PDF；覆盖数值预测、方向、因果、未到期和未披露五类观点。

不要求一次标注整个市场。先人工整理 20–30 个观点、至少 60 个关联数字/文字事实、至少 10 个第二轮变化；标注分歧记下原因，不强行当成唯一绝对答案。详情见 [资料清单](14_资料准备清单.md)。

## 3. 工程测试层

| 层 | 必须覆盖 |
|---|---|
| 单元 | 单位、负值、期间兼容、同比、单季推导、百分点、状态聚合、memory compiler |
| 契约 | Zod/DTO/OpenAPI、一致错误体、证据 ID、provider 录制样本、parser manifest |
| 集成 | 真 PostgreSQL 事务、job lease、进程重启、幂等确认、草稿恢复、文件 Range |
| 浏览器 E2E | 上传、公司确认、进度恢复、证据高亮、修正重算、保存、历史、下一轮 |
| 真实分析评测 | 真实 PDF + 当前可用模型；冻结来源与运行配置，人工对照 |
| 获取验收 | 至少沪/深各一家公司自动发现并取得正确最新完整财报 |

网络抓取测试分“录制响应的稳定回归”和“实时官方源 smoke”；前者不能证明今天的自动获取仍通，后者不要求每次普通单元测试跑网。

## 4. 确定性通过项

以下在固定测试集必须全部通过：

- 所有展示引用都指向存在且正确的文件/页码；数字引用含期间和单位依据。
- 零值与缺失区分，万元/亿元转换、比例/百分点、累计/单季测试全通过。
- 全年预测未到期不被一季度差距直接判定失效。
- 相关性不能单独令因果观点变为 SUPPORTED。
- 已确认状态不被新草稿覆盖；重复确认不新增版本。
- Worker 重启后能从最近完整检查点继续；旧租约不能写迟到结果。
- 用户修正进入第二轮，原始研报观点和历史状态保持不变。
- 不同工作区不能读取项目、PDF、证据、SSE、导出；模型密钥不在前端产物。

## 5. 质量目标（交付前实测，不是现有成绩）

| 指标 | 初始目标 | 计算方式 |
|---|---|---|
| 关键观点召回 | ≥85% | 人工标注关键观点中被忠实提取的比例 |
| 可用观点精确率 | ≥90% | 提取观点中具有原文依据且原意正确的比例 |
| 已使用数字事实准确率 | ≥95% | 数值+期间+单位+口径全部正确才算对 |
| 原文定位正确率 | 100% | 已展示引用能定位到相应原页/单元格 |
| 核验结论可接受率 | ≥85% | 人工认可状态及理由，不以文字相似度打分 |
| 核心高风险误判 | 0 个 | 错主体、错期间、伪造引用、提前证伪、无依据因果支持 |
| 第二轮连续性 | 100% 固定用例通过 | 同一观点、用户修正、旧问题、历史版本 |

小样本成绩不能推断整个金融市场准确率。报告必须列出分母、资料范围、失败案例、模型/提示词版本和是否使用缓存。

## 6. 人工盲审

先由研究者标注研报核心观点与目标，再由另一轮人工审阅结果，不让模型自己打满分。每个争议分类为提取错、期间错、事实错、逻辑错、原因臆测或展示误导。优先修影响核心结果的问题，不以无关 UI 边角 bug 拖延主闭环。

## 7. 三条必须留下的演示录像/记录

1. 从真实 PDF 到第一版研究，不预先手写观点。
2. 一条复杂观点拆分、财报事实与来源、高于/低于预期的解释。
3. 第二期更新使用既有 Memory，改动前后对照与用户修正保留。

这些既是验收证据，也是向外展示金融 × AI 能力的核心材料。展示可解释的研究过程，比展示十个技术面板更有竞争力。

## 8. 验收报告产物

`reports/acceptance/<date>/` 包含版本 manifest、数据集清单与权属说明、结果 JSON、指标表、失败样例、运行耗时/成本、浏览器录屏或截图、恢复测试结果。未通过项记录真实影响和下一任务；未执行的测试标记“未执行”，不写成通过。
