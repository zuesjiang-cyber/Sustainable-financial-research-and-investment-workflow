# 14 资料准备清单

本次不代收集资料。下面是为了开发和真实验收需要准备的东西；**日常成品使用只要求用户上传研报**，不要求每次手工做这一整包。

## A. 先准备一个可以讲清楚的主案例

- [ ] 一家沪深上市公司：名称、证券代码、交易所。
- [ ] 一份正式公司研报 PDF：有明确研究观点、发布时间、预测期间；最好 10–40 页、文本可复制。
- [ ] 第一份后续正式财报完整 PDF：可检验研报中至少两个观点。
- [ ] 再后一份正式财报完整 PDF：至少有一个观点出现变化或新增证据。
- [ ] 必要的比较年报/同期报表：只有现有两份无法提供比较数时才补。
- [ ] 各财报官方公告页 URL、公布日期和报告期；作为自动获取结果的人工对照。
- [ ] 确认材料可以在私人开发测试中使用；如要公开演示，另确认展示/分发权限。

研报必须早于用于验证其预测的财报披露，才能展示“先有判断、后有证据”的更新价值。不要选只有泛泛看好而无业务/指标判断的报告。

## B. 最小人工答案表

可用一张 Excel/CSV，中文即可，不要求写代码：

| 字段 | 填什么 |
|---|---|
| 公司、研报文件名、研报页码 | 主体与原始来源 |
| 原观点原句 | 研报真正说的话，不先替它改写 |
| 观点类型和目标期间 | 数值预测、方向、原因、定性；目标哪一年/季度 |
| 你认为该查什么 | 对应指标、业务数据或解释段落 |
| T1 事实、单位、口径、页码 | 第一份财报里能确认的内容 |
| T1 应有判断与理由 | 支持/部分支持/削弱/待验证；允许有争议 |
| T2 新事实与页码 | 第二份财报新增或改变什么 |
| T2 应有变化 | 哪条观点为什么变化 |
| 原因是否公司明确披露 | 是则抄出处；否则标“推测/未披露” |
| 用户修正样例 | 你希望系统下一轮记住的一条真实修正 |

主案例先做 6–10 条观点，不必把所有页标一遍。至少包括：一个数值兑现、一个存在差距、一个未来未到期、一个因果未充分披露、一个第二轮得到补充。

## C. 完整验收再补的材料

- [ ] 另外两家沪深公司的研报与两期财报，共至少三家公司。
- [ ] 一份扫描或图文混合 PDF，用于 OCR 与原页定位。
- [ ] 一组累计/单季数据，能检查 YTD 到单季转换。
- [ ] 一组万元/亿元或百分比/百分点口径，能检查单位处理。
- [ ] 一组归母/合并或业务分部数据，能检查范围不混用。
- [ ] 如容易取得，一份更正/重述财报，用于验证资料版本；没有时先用清晰标记的人工构造回归样本测试版本逻辑。

真实集最低约 20–30 条观点、60 个事实引用和 10 个更新变化。构造样例和真实披露分目录，不混算真实模型成绩。

## D. 环境信息

- [ ] 能调用 Ling-3.0-flash-Fin 的服务端 endpoint、准确 model ID、API key。
- [ ] 实际调用限额/单价，或明确目前未知；密钥通过私密环境变量提供，不放资料文件。
- [ ] 运行位置：本机或私有云；云端机器规格、可用磁盘、域名/HTTPS 方式。
- [ ] 云端展示的登录提供方（OIDC）与允许访问的账号；本地展示不需要 OIDC。
- [ ] 允许每轮/每月的模型费用预算，人民币或服务商计费币种均可。

不需要购买向量数据库、提供股票交易账号、准备多 Agent 平台或自己创建 memory 数据库。

## E. 推荐交付目录

```text
demo-materials/
  manifest.csv
  case-01/
    research-report.pdf
    filing-t1.pdf
    filing-t2.pdf
    comparison-report.pdf       # 需要时
    expected-theses.csv
    expected-facts.csv
    expected-updates.csv
    notes.md                    # 你认为哪里最值得展示
  case-02/
  case-03/
```

manifest 列：case_id、文件名、公司代码、角色、报告日期、财务期间、官方 URL、文本/扫描、使用权限说明。开发程序自己计算 SHA、解析页码和提取事实，不把这些技术活转嫁给资料准备者。

## F. 准备优先级

**先给 A+B 的一家公司主案例和可用模型环境就能开始。** C 用于完成验收，D 的云端部分到部署任务前提供即可。没有测试答案不妨碍先写管线，但不能凭系统自己产生的答案证明它做对了。
