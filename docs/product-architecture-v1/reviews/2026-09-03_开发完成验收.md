# FinTrust V1 开发完成验收

验收日期：2026-09-03。对象：本地 `fintrust-research` 当前工作区，分支 `codex/continuous-research`，HEAD `13a42f6`，包含尚未提交的新代码。本次未拉取或核对远端，不代表对 GitHub 同步状态的确认。

## 结论

**页面原型和一批后端模块已经完成，但“上传研报 → 自动核验 → 保存研究 → 新财报继续更新”的真实主链路尚未接通，不能认定成品 V1 开发完成。**

这不是需要重新设计架构，也不是优先修一批边角 bug。下一轮应复用已有模块，完成一次真实输入驱动、可以持久保存的端到端集成。

## 已完成的有效工作

| 部分 | 当前实际成果 | 尚缺的连接 |
|---|---|---|
| 页面 | 上传页、观点卡片、判断编辑、证据侧栏、两轮展示 | 数据来自固定前端对象，未调用新后台 |
| 领域与存储 | 共享类型/Zod、PostgreSQL 仓储、文件存储、任务队列与 Worker 类 | V1 API、Worker 业务处理器与启动入口未接入 |

| 财报发现 | 巨潮查询适配器、公告元数据映射、离线样例回退 | 下载原件、解析、选择当前核验材料并联动主流程 |

## 必须先完成的四项 P0

### 1. 把真实文件送进后台，替换首页的固定回放

证据：

- [ReportUploadView.tsx](../../../src/components/research/ReportUploadView.tsx) 第 18–31 行：选文件或拖入文件后，仅传递 `file.name`，没有传递文件内容。
- [ReportFirstContainer.tsx](../../../src/components/research/ReportFirstContainer.tsx) 第 59–108 行：`handleStartAnalysis` 没有使用输入参数；经过多次 `setTimeout` 后构造固定圣邦股份研究草稿。该组件没有后台请求。
- [server.ts](../../../server.ts) 第 7–19 行、[app.ts](../../../src/server/app.ts) 第 80 行起：运行入口仍是旧 `/api` 路由，没有挂载设计中的 `/v1` 上传/运行接口，也没有启动 ResearchWorker。
- 仓库引用检索显示，新的 ResearchAgent 实例化调用出现在测试文件中；生产入口未连接此核验链路。

实际页面复现：打开 `http://127.0.0.1:3000`，点击“汇顶科技 603160”样例，结果却显示“300661 · 圣邦股份”。页面上的解析、财报查询和 Agent 进度由固定延时生成。

**完成标准：文件内容不同会驱动不同的真实解析和研究结果；前端只展示后台 run、draft 和 evidence 的返回数据。**

### 2. 让“保存研究”和第二轮更新真正使用持久状态

证据：

- [ReportFirstContainer.tsx](../../../src/components/research/ReportFirstContainer.tsx) 第 383–394 行：确认只调用 React 状态更新，没有请求或持久化。
- 同文件 `handleUpdateRound2`：第二轮仍为预设年报数字构造的新对象，没有读取新披露或数据库中的上一版状态。
- [draftsRepo.ts](../../../src/server/repos/draftsRepo.ts) 第 74 行起已有 `confirmDraftToState` 事务实现，涉及研究版本、快照与用户修正；应把它接通并实测，而不是再新增另一套“Memory”。

实际页面复现：输入“验收测试：此备注应在刷新后保留”，点击保存，界面显示“已确认入库”；刷新页面后回到上传入口，研究结果和备注没有恢复。结合确认函数实现，可确认此流程只存在于页面内存。

**完成标准：保存后刷新及重启服务能恢复；第二轮沿用稳定 thesisId、当前 revision、人工修正和未解问题，生成相对于上次确认状态的 diff。**

### 3. 核验必须尊重观点含义，原因必须来自证据

证据：

- [researchAgent.ts](../../../src/server/agent/researchAgent.ts) 第 159–180 行：趋势向上通过“当前值是否为正”判断，没有按 `comparePeriod` 比较。
- 同文件第 214–229 行：无条件加入固定的管理层原因和行业假说，并复用事实引用列表。这不是从管理层原文提取原因。
- 此 ResearchAgent 当前是规则计算类，没有模型驱动的找证据、补材料、再判断循环；不能用类名或注释认定六工具 Agent 已完成。

在隔离副本执行的两个合成输入探针：

| 输入 | 实际输出 | 应有行为 |
|---|---|---|
| 证据、事实、计算均为空 | `UNRESOLVED`，但仍返回“管理层指出供应链降本与高规格模拟产品出货放量系主要驱动因素”，引用为空 | 未取得原因证据时，披露原因应为空，并说明尚无法解释 |
| “经营现金流同比改善”，上期 2 亿元、本期 1 亿元，同一 CAS 合并年度口径 | `SUPPORTED`，称“呈现向好态势” | 根据同口径前后期比较识别下降；不能把正数等同于改善 |

这些是程序合成测试，不是对任何真实公司的财务判断。

**完成标准：模型负责拆观点、选择证据和解释；确定性代码负责算数与条件比较。披露原因逐条对应原文，假说独立标注，缺失时不填模板答案。**

### 4. 财报原件和 PDF 定位真正可用

证据：

- [officialFilingProvider.ts](../../../src/server/disclosures/officialFilingProvider.ts) 第 100–225 行：实现查询与元数据返回，网络失败回退离线样例。返回公告列表不等于完成 PDF 下载、解析和最新材料入包。
- [parser.py](../../../python/document_parser/parser.py) 第 39 行起使用 pdfplumber；文本块 bbox 为统一的大页面区域，表格单元格复用整表 bbox。代码中没有实际 OCR 调用。
- [PdfEvidenceViewer.tsx](../../../src/components/research/PdfEvidenceViewer.tsx) 第 81–132 行：展示文字引文和坐标数值，没有渲染 PDF 原文件或高亮。

实际点击“查看原件 P1”：打开的是预设引文、页码和坐标卡片，不是 PDF 页面。

**完成标准：公告查询后下载并保存原件，记录文件 hash 和披露时间；每条引用能打开对应 PDF 的实际页并定位。离线预览与实时查询结果按真实覆盖范围显示。**
