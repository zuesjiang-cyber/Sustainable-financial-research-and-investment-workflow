# 发给开发 Agent：修订实施方案

你的主流程和九个工作包方向保留。请先修订实施计划，不要立即按当前三个默认降级建议开始全面开发。目标是完成既定的研报观点核验与持续研究 V1，不是只做预置样例页面。

## 1. 环境问题不要直接改写成品能力

数据库保持单一 PostgreSQL 目标；本地没有命令或服务，就列出准确环境前置条件与可用连接方案。StorageAdapter 只管文件存储，不代表数据库方言兼容。不要同时承诺 SQLite/PostgreSQL 无缝切换。若确实需要把最终部署改为单一 SQLite，请单独提出架构变更、队列实现和验收方案，等待确认。

先尝试项目内 Python 虚拟环境运行 Docling，不修改全局 Python。PDF.js 继续负责 PDF 阅读与可选文本快取；真实表格与 OCR 解析仍是成品实现内容，不能只留一个空适配接口。安装失败请记录具体错误，不用“全局目录受保护”概括为无法实现。

## 2. 最新财报必须真实取得

实现并实测至少一个适用的官方来源查询/下载路径，记录公司、报告期、公告发布时间、修订关系、查询时间和文件 hash。内置真实财报包只能用于回归/离线预览，界面显示其覆盖时间；不能用旧材料冒充已经查询到最新财报。移除“100% 确定性”承诺。

## 3. 恢复完整 Agent 和观点语义

按 contracts/agent-tools.json 接入六个工具，补回 search_evidence 和 request_disclosure。Agent 根据观点决定找什么，缺证据时搜索/读取/补材料，再判断是否足够。复用 continuousAnalyzer、researchTools 和 Decimal 计算，不新建一套重复逻辑。

后台保留有效观点，前台只折叠显示重点。覆盖数值、方向、因果和定性观点；研报原有门槛、系统建议门槛、用户确认门槛分开。保留四种核验状态与 NOT_DUE/IN_PROGRESS/DUE：全年预测未到期不能被单季数据直接证伪。

## 4. 把持久运行和 Memory 写成明确交付

任务 001 增加实际 Worker、jobs、lease、checkpoint、run_events、持久草稿及恢复测试，不能继续用内存 Map 保存运行结果。

任务 005 不只继承备注：第二轮沿用稳定 thesis ID、观点 revision、核验标准、最近确认结论、用户判断和未解问题。新财报更新 assessment，原研报及历史版本保持不变。修改标准使旧核验失效并重算；用户个人判断独立保存。

## 5. 补全最终交付与验收

任务 008 包含原设计的私有部署、必要登录、数据迁移与恢复；任务 009 依赖 002–008，不能漏前端或部署。把原成品文档里已列的缓存、并发和模型预算纳入对应任务，不重复造新平台。

验收至少展示：

1. 上传此前未跑过的真实研报，自动提观点并取得对应官方财报。
2. 点击数字/引文回原 PDF；能解释一个差距以及一个仍未证实的原因。
3. 用户修改一项核验标准并重算，再保存 v1。
4. 新一期财报更新同一观点，继承人工修正，处理旧问题，形成 v2 diff。
5. 刷新页面和重启 Worker 后恢复任务/草稿。
6. 换一家公司的材料再次运行，证明不是为固定样板公司硬编码。

先返回修订后的实施计划、具体复用模块、需要的真实环境信息和各阶段验收。无需重写完整 PRD，也不要扩大前端复杂度；具体编码仍按已分配工作包执行。
