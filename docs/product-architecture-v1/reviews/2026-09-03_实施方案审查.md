# FinTrust 成品实施方案审查

日期：2026-09-03。项目：fintrust-research；当前分支 `codex/continuous-research`，HEAD `13a42f6`，工作区有既有未提交变更。

审查对象：用户粘贴的《FinTrust 成品 V1：研报观点核验与持续研究实施方案》。本次按“待批准的实施计划”审查，不把其中 Proposed Changes 当成已经完成的代码。没有修改业务代码、安装环境或改写原成品架构。

结论：**DONE_WITH_CONCERNS；主流程保留，修订后再按完整成品计划执行。** 核心问题不是用了不同技术，而是若照目前文字执行，若干必需能力可能变成可选适配或预置数据演示。

## 1. 范围复核

用户目标仍是：上传研报→自动拆观点→最新财报事实→观点核验→确认状态→下一期沿用原研究。没有必要增加“多数据库方言平台”，也不需要为每个阶段从头新建一套框架。

保持既定完整 V1 范围，分阶段交付；阶段 A 可先展示文本 PDF，但不能据此把扫描件/表格能力从成品完成条件移除。架构变更以用户后续确认或更新的决策文档为准，本审查没有自行改变数据库选型。

## 2. 架构：六项需要修订

### A1. SQLite 可用于本地单用户，但“双库无缝切换”尚无方案支持

粘贴计划把 StorageAdapter 与多数据库支持混在一起。原 [架构第 2 节](../02_总体架构与技术选型.md) 中，StorageAdapter 只管 PDF/解析文件的磁盘或对象存储；数据库明确为 PostgreSQL，任务领取依赖其事务和锁语义。

SQLite 并非不能维护研究状态，但建表近似不代表队列、锁、JSON 查询、数值类型与迁移语义完全等价；SQLite 同时只允许一个写事务。[SQLite 事务文档](https://www.sqlite.org/lang_transaction.html)

建议：这次保持单一 PostgreSQL 目标，实现一个经过测试的数据库后端。需要本地免服务版本时，再明确采用单一 SQLite 的部署边界与任务领取实现，不提前宣称改环境变量即可切换。保留一份 DDL 不能算第二种数据库已支持。

环境核查：本次 PATH 中未找到 psql/postgres/pg_ctl/docker/uv；这不等于全面证明机器没有服务。尤其 psql 是客户端，不能叫数据库守护进程。环境缺依赖应列成安装/连接前置条件，不自动升级为重做数据库架构的理由。

### A2. PDF.js 可以做快速文本通道，不能据此把完整解析变为“以后适配”

PDF.js 的页面 API 可以读取已有文本和页面结构；无结构树时也可能返回 null。拥有文本和坐标不等于财务表格、单位列、跨页表与 OCR 已经实现。[PDF.js 页面 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)

主方案可保留 PDF.js 阅读/文本快取，但成品仍需实际可用的表格与 OCR 通道，统一输出既定 parser manifest。若改用其它解析器，应以真实财报样本证明满足同一契约，而不是仅声称“高精度”。

本机 Python 3.11 可导入 venv；项目虚拟环境可以隔离安装包，不必写全局 Python 目录。[Python venv](https://docs.python.org/3/library/venv.html) 本次没有安装 Docling，因此不声称其全部依赖已验证。先尝试项目内环境，若失败报告具体依赖、网络或权限错误。

### A3. 本地财报池可以保留，但必须和“最新自动获取”分开

固定真实文件适合回归测试，也可作为用户补充材料。它证明的是“对这些资料可以研究”，不是“今天查到了最新财报”。删除“确保链路 100% 确定性”的泛化承诺。

实际获取必须记录证券主体、公告发布时间、报告期、修订版本、查询时间、文件来源与 hash。用预置材料时清楚显示资料覆盖时间和离线状态。抓取失败不能显示“没有新披露”，更不能把特定公司的固定文件交给另一家公司。

公开查询接口需真实联调确认 URL、参数、分页和访问条件，不能仅写“标准接口”就认为集成有基础。主案例自动获取和另一家公司换输入测试应尽早执行。

### A4. Agent 工具从六个缩为四个，补查能力没有落实

原 [工具契约](../contracts/agent-tools.json) 包含 find_facts、search_evidence、read_evidence、calculate_metric、request_disclosure、submit_assessment。计划遗漏 search_evidence 和 request_disclosure。

需要恢复：找不到解释时搜索财报原文；缺比较材料时申请补充披露；读取后根据证据是否足够决定继续或结束。工具可以复用现有实现，不要求新建多个自治 Agent。成熟度也应保留 NOT_DUE/IN_PROGRESS/DUE，而不只列两个状态。

### A5. “有 runs 表”不等于任务已经能恢复

计划底座强调类型、表和仓储，却没有明确 Worker、jobs、lease、checkpoint、run_events 的实现与验收。当前 [app.ts](../../../src/server/app.ts) 第 85 行仍把草稿保存在 Map，并存在 1 小时 TTL；不能继续沿用为成品运行方式。

补上最小完整后台任务：API 入队后立即返回；Worker 执行；阶段产物与草稿持久化；重启从检查点继续；确认研究事务和幂等。用户关页面不用重新付费跑整份研报，这是主路径能力，不是额外高可用工程。

### A6. Memory 不能只等于继承备注

计划目前重点描述人工备注继承，尚不足以表达研究状态。第二轮必须同时继承：稳定观点 ID、当前核验标准、原始出处、最近已确认 assessment、用户判断和未解问题。

新财报应更新 assessment，不重新抽一组不相干的观点，也不改写原研报。改标准需要重算；只改个人看法应与系统核验分开。第二轮主案例应是“新增财报→原观点更新”，不是必须再上传一份研报。

## 3. 代码质量：两项收口

**Q1. 已有能力优先接入。** 当前 continuousAnalyzer 有工具调用循环，researchTools 有搜索/读取/计算，researchModel 有模型适配，buildResearchContext/projectRepo 有研究状态与修正逻辑，fintrustEngine 使用 Decimal。新增 V1 服务应做适配或抽取，不平行复制同一套计算与 Memory。

**Q2. 不把观点强制压成 3–5 个数字门槛。** 前台可默认展示少数重点组，后台保留有效观点。原始研报有定性、因果和风险命题，未给数值目标时标记系统建议标准，不能把“增长较快”自行写成研报提出“增长 20%”。

## 4. 测试：五类缺口与最小验收图

```text
真实研报 PDF
  ├─文本型/扫描型 → 自动观点 + 原页定位             [E1]
  └─公司不明确   → 确认后继续                    [E2]
             ↓
最新官方财报 → 成功：披露时点与报告期正确          [E3]
             └失败：显示已覆盖材料，不冒充最新     [E3]
             ↓
逐条核验 → 期限/口径/因果 + 证据补查             [E4]
             ↓
修改标准 → 重算；修改个人判断 → 独立保存           [E5]
             ↓
确认 v1 → 新一期财报 → 同一观点 + 修正 + 问题 → v2 [E5]

刷新/断线/Worker 重启 → 恢复任务与草稿             [E6]
另一家公司 + 干净部署 → 不是固定模板或原机器特例     [E7]
```

五类缺口：①扫描/表格与公司歧义；②真正获取最新资料及失败分支；③金融期限/口径/因果和补查；④修改标准后的重算与持续状态；⑤重启恢复、替换公司和干净部署。现有计划的两个测试文件名与 happy-path 手工步骤不足以说明这些已覆盖。

测试建议：保留既有计算基线；对新的提取/核验 prompt 使用原 [验收文档](../12_验收与评测.md) 的人工标注资料集，真实模型结果与回放分开统计。最终任务 009 依赖 002–008 全部就绪，尤其不能漏掉前端和部署。任务 008 恢复原定的私有部署、登录与迁移，而不只做备份。

### 潜在失败与用户表现

| 路径 | 现实失败 | 当前计划的测试/处理说明 | 建议用户表现 |
|---|---|---|---|
| E1 | OCR/列头识别错，数值串期 | 未具体说明 | 指出无法可靠读取的来源，不当作确定数值 |
| E2 | 多公司研报识别成同业 | 未具体说明 | 一次点选主体后继续 |
| E3 | 网络失败时加载旧财报包 | 有回退，未明确“最新”标识 | 展示覆盖日期及本轮查询失败 |
| E4 | 全年目标被一季报提前判错 | 有成熟度字段，未列回归用例 | 待验证 + 阶段信号 |
| E5 | 改核验标准仍保存旧结论 | 只写微调判断，未明确重算 | 提示受影响项重新分析 |
| E6 | Worker 重启、草稿丢失 | 未明确检查点恢复 | 页面恢复后继续当前任务 |
| E7 | 固定公司样例通过，其它公司无效 | 只举特定主案例 | 换输入后仍走真实链路 |

其中 OCR 错数、旧资料冒充最新、任务/草稿丢失是三类关键设计缺口；这是计划审查，不表示新实现已被测试出这些故障。

## 5. 性能：两项明确继承原设计

文件/解析按 hash 缓存，第二轮复用已解析资料，不整包重跑；长 PDF 解析和模型调用由 Worker 执行，限定并发、调用预算和超时。计划应注明这些在任务 001/004 的交付中，而不只给前端进度环。没有实际运行数据，本次不预测解析耗时或模型单轮成本。
