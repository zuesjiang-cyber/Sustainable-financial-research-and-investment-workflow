# 01 产品定义与交互（PRD）

## 1. 产品解决什么问题

目标用户是已经阅读公司研报、需要跟踪公司兑现情况的研究员、投资经理助理和高投入个人研究者。他们的问题不是「看不懂财报摘要」，而是：之前为什么看好这家公司？新财报究竟改变了哪些判断？下次应该继续盯什么？

当前工作通常要在旧研报、最新财报、笔记之间往返。产品把这个往返过程变成一个可继续更新的公司研究项目。首要价值是缩短复核时间并保留推理链，而不是替用户给买卖指令。

商业吸引力假设：持续跟踪多家公司的研究者，会为可靠的观点复核与记忆付费。此项尚未经用户验证，不把泛金融从业人数当作付费市场规模。验证方法是让 5 位目标研究者使用自己的研报，完成一次首次核验、一次后续更新，观察他们是否愿意重复使用，以及是否比自己手工复核更快。

## 2. 用户唯一主路径

首页「上传研报」→ 自动分析进度 → 公司研究页 → 保存研究 → 新一期变化。

首次上传不要求用户先写 thesis、建立指标字典、上传 JSON 或设置 Agent。公司与日期只有识别不明确时才询问。后台取得财报失败时，在同一进度页提供「重试 / 上传财报补充」，保留已经完成的观点提取。

## 3. 完整 P0 需求

| 编号 | 用户能力 | 成品完成条件 |
|---|---|---|
| P0-01 | 上传真实研报 PDF | 文本型与常见扫描型 PDF 均能处理，原文和页码保留 |
| P0-02 | 自动提炼研究观点 | 提取观点原句、原始依据、时间范围、验证标准；原句可定位 |
| P0-03 | 自动找到财报 | 公司匹配后取得截至分析时点的最新正式报告及必要对比报告，展示覆盖日期 |
| P0-04 | 财报事实提取 | 表格和文字事实有公司、期间、单位、合并口径和来源 |
| P0-05 | 逐条核验 | 每条观点有状态、事实、差距、原因层次、下一步问题 |
| P0-06 | 证据回看 | 点击引用打开正确文件及 PDF 页，突出原句或表格单元格 |
| P0-07 | 人工修正与保存 | 可以调整观点/核验标准、排除无用项、写当前判断并保存版本 |
| P0-08 | 持续更新 | 下一次沿用同一观点 ID，展示新旧变化，已确认的历史可回看 |
| P0-09 | 简洁研究界面 | 默认只有观点与变化，内部工具轨迹收在详情而非主页面 |
| P0-10 | 稳定的异步执行 | 刷新、关闭页面或 Worker 重启不丢任务、草稿和已确认状态 |
| P0-11 | 私人部署与数据可携带 | 本地或私有云运行；云端登录；导出研究及来源清单 |
| P0-12 | 新披露检查 | 手动检查；按项目自愿开启每天一次检查，生成待审草稿 |

## 4. 研究页呈现什么

顶部：公司名称、最新覆盖财报、上次保存时间、当前版本、一个「检查最新财报」按钮。

核心列表默认显示最重要的 3–8 个观点组，其余折叠为「更多观点」。不为了界面简短而丢弃后台已提取的观点。

每个观点组展示：

1. **研报怎么说**：忠实保留原意，原句在展开区域。
2. **财报说明了什么**：最相关的 1–3 个事实和比较值。
3. **现在怎么看**：支持 / 部分支持 / 削弱 / 待验证，以及一句有实质信息的解释。
4. **为什么有差距**：披露已说明的原因和仍需验证的解释分开。
5. **接下来盯什么**：下一期指标、需要的信息、待回答问题。

第二轮优先展示「本次变化」，例如：毛利率观点由“待验证”变为“得到支持”，但产品结构是否驱动改善仍待验证。未发生变化的观点折叠，随时可展开。

## 5. 必要的人机交互

- 自动识别公司有多个候选：展示证券代码和名称，用户点选一次。
- 研报观点过于宽泛：系统先给出建议核验标准，标记「系统建议」；不伪装成研报原文。
- 用户改观点或标准：仅重跑受影响观点，已有文件和事实复用。
- 用户改当前判断：保存为用户意见，系统分析仍可展开查看。
- 财报获取不完整：展示目前覆盖范围与仍缺材料；其它观点继续产出。
- 最后点击「保存本次研究」：草稿变成已确认状态；不要求每条机械点击确认。
- 初次分析失败：仍能看到提取成功的观点、失败发生在哪一步和继续入口。

## 6. 两个产品层面的重要取舍

**自动化不等于静默覆盖。** Agent 自动收集、分析、生成草稿，用户一次确认写入长期状态。这让“我的研究判断”和“模型本轮输出”不会混为一谈。

**观点是主角，文档是证据。** 资料列表、事实表、运行轨迹是支撑视图，不各自成为主导航。用户不必先理解系统数据结构。

## 7. 产品评估

第一轮访谈记录以下数据，作为是否继续投入的依据：

- 研究者能否在 30 秒内理解首页要做什么。
- 使用自己的研报后，有多少核心观点被提对，哪些拆分需要修改。
- 从打开工具到形成可用更新，人工实际参与多少分钟；与其原流程对照。
- 结果中哪些原因分析足以进入自己的研究笔记，哪些只是套话。
- 第二份财报到来时是否愿意主动回来；是否认可保留历史与纠错的价值。

这些是待测指标，不是本项目已经达到的结果。付费方式、市场规模和竞品优劣不在没有实测时写成事实。

## 8. 完成定义

真实用户不用手写观点，只上传研报，即可获得有来源的逐条核验；随后加入下一期财报，能够沿着相同观点更新并保留自己的修正。**只有首次摘要，没有后续状态；或只有漂亮回放，没有真实自动获取，都不算这个成品完成。**
