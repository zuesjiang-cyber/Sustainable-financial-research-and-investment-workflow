# 18 产品完整设计稿 · AI 驱动的观点维护与证据分级

状态：**已对齐**（2026-09-13）。本文档是画面一、画面二的实现依据。

---

## 0. 一句话定位

一个以**用户已有观点**为长期资产、以**新披露**为触发、由 **AI 驱动判断**、由**代码守住事实**的投研状态维护系统。

它不生成摘要。它对用户既有的信念做差分，并把差分结果严格分成**事实**与**推论**两类。

---

## 1. 核心分工：AI 驱动判断，代码守住事实

AI 是那个分析师。它决定：看哪份文件、检索什么、比较什么、推断什么、下一步该向公司要什么、怎么用克制的话把推断说清楚。

AI 唯一不做的事是**造假**。四条硬边界：

| 边界 | 内容 |
|---|---|
| 不编数字 | 缺操作数时拒绝计算，输出拒绝理由，不产出一个看起来合理的数 |
| 不做算术 | 阈值、差额、同比、百分点一律由确定性代码用 Decimal 计算 |
| 不把推论说成事实 | 每一条产出必须自报是哪一类 |
| 不把公司的话当证明 | 管理层单方归因永远不构成因果证据——归因方即被评价方 |

这四条边界不是对 AI 的削弱，而是这个产品能被信任的原因。**事实与推论的区分本身就是 AI 驱动的体现**：两者都由 AI 产出，但它必须自己说清哪句是哪一种。

## 2. 四个画面

```
        [新披露到达]
              │
              ▼
   ① 分析动画          agent 工作的抽象动效，不是过程日志
              │
              ▼
   ② 分析结果          事实 / 推论 / 本次未涉及，每一条可溯源
              │  用户确认
              ▼
   ③ 研究台            沉淀为安静的观点列表（已实现）
              │  点任意数字或原话
              ▼
   ④ 证据侧栏          溯源：页码、单元格、逐字原话、计算链
```

### 2.1 画面一：分析动画

**不看机器干活。** 用户不需要盯着管线一步步走。

- 新披露进来 → 一段有呼吸感的 agent 工作动画
- 动画下方配**一行真实的话**，说明当前实际在做什么（"正在核对三季报利润表"），随阶段变化
- 动画结束 → 直接落到画面二

那一行真实的话是必需的：没有它，动画就是假转圈。它只有一行，不构成过程展示。

**不使用**：虚假的平滑百分比、编造的剩余秒数、token 计数、工具 JSON 原文。

### 2.2 画面二：分析结果（事实 / 推论 / 未涉及）

这是产品的核心画面。AI 把本轮发现的变化分成三块。

#### 事实 —— 纯粹二元，只有成立与不成立

事实**没有程度**，不需要用户表态，它就是真的或不是。每条都可点开溯源。

| 事实 | 判定 |
|---|---|
| 全年毛利率 51.46%，门槛 ≥ 51.00% | **成立** |
| 现金利润比 0.85，门槛 ≥ 0.90 | **不成立** |
| 年报第 21 页披露了应用领域收入结构 | **成立** |
| 年报披露了分产品毛利率 | **不成立**（没有该披露） |
| 存在可独立验证的因果证据 | **不成立**（只有管理层说法） |

事实分三种来源类型，各自的成立门槛不同：

| 类型 | 成立的条件 |
|---|---|
| 数值事实 | 证据性质为经审计或未经审计的实际数；口径门禁全过；可绑定到具体单元格与列头；核验窗口已到期 |
| 披露事实 | 有逐字引用、页码、标题路径、文本指纹，且属本轮冻结资料包 |
| 证据存在性事实 | 例如"是否存在可独立验证的因果证据"——二元判定，管理层说法不算 |

#### 推论 —— 克制、合理、明确标注

推论是 AI 的判断。它必须自带三样东西，**写不出这三样就不输出**：

```
推论  <一句克制的判断>
依据  <可核对的事实或数字>
局限  <为什么不能确认>
缺口  <补上什么才能确认>
```

实例：

> **推论** 毛利率的韧性可能部分来自成本端价格回落，而非产品结构升级。
> **依据** 营业成本同比 +12.94%，低于营业收入同比 +16.46%，方向一致。
> **局限** 年报未做量价拆分，既不能确认也不能排除。
> **缺口** 分产品或分应用的两期毛利率。

> **推论** 现金利润比连续两期低于门槛，可能反映回款周期拉长。
> **依据** 0.83 → 0.85，两期同口径实际数。
> **局限** 缺应收账款与存货明细，无法定位缺口来源。
> **缺口** 应收账款账龄与存货构成附注。

两条铁律：

- **推论永远不会升级成事实**，无论 AI 多有信心
- **事实永远不会被稀释成推论**，不会因为"可能还有别的解释"就含糊掉

措辞上"克制"的具体含义：用"可能""方向一致""不能排除"，不用"充分验证""显著增强""逻辑得到确认"。

#### 本次未涉及 —— 覆盖声明

既不是事实也不是推论，是一句关于覆盖范围的声明：

> 本次披露未涉及该观点，沿用上一轮状态，**未被重新验证**。

这一档必须存在且可见。删掉它就等于让系统假装核验过没核验的东西。

### 2.3 画面三：研究台（已实现）

确认后沉淀为安静的观点列表，每条四行：标题、核验门槛、本轮变化、结论与下一步。渐进披露三层，详见 §5。

### 2.4 画面四：证据侧栏（已实现）

从画面二或画面三点任意数字／原话打开，不跳走当前位置。按核验真实的三层组织：

```
第一层 · 来源真实性    引用是否属于本轮资料包、是否逐字、在哪一页
第二层 · 可比性与计算  六项口径检查 → 通过则 Decimal 计算，不通过则拒绝并给理由
第三层 · 命题关系      支持 / 反驳 / 仅相关 / 缺信息；因果类另跑一次短校验
```

## 3. 证据性质分层

业绩预告里的数字和年报里经审计的数字不是同一种东西。若不分层，系统会拿一个未经审计的区间预测把观点判成"已验证"。

| 性质 | 典型出处 | 对数值事实的效力 |
|---|---|---|
| 经审计 | 年报、经审计半年报 | 可支撑**成立** |
| 未经审计实际数 | 一季报、三季报 | 可支撑**成立** |
| 业绩快报 | 快报公告 | **上限为不确立**，只能生成推论 |
| 业绩预告 | 预告公告 | **上限为不确立**，只能生成推论 |
| 叙述性披露 | 经营讨论、公告正文 | 支撑披露事实；管理层归因不支撑因果 |
| 第三方 | 研报、新闻 | 不作为事实源，仅作线索 |

降权发生在判定**之前**：

```
若数值证据的性质 ∈ {业绩快报, 业绩预告}
  → 该事实不得判为"成立"
  → 但可以生成一条推论，并在推论中说明"依据为未经审计的预告，待正式披露确认"
```

效果：**预告能改变用户的注意力，不能改变系统的结论。**

## 4. 观点的来源

用户"已经拥有的观点"不一定在研报里。

| 来源 | 原始表述 | 核验门槛从哪来 |
|---|---|---|
| 研报提炼 | 研报原句 + 页码 | 研报明示，或系统建议后用户确认 |
| 研报提炼后用户改写 | **两者都保留** + 改写理由 | 同上 |
| **用户自建** | 用户原始表述 + 录入时间 | 系统必须追问到可核验：建议门槛、标明是**系统建议**、用户确认后生效 |

自建观点往往宽泛（"客户结构在改善"）。系统的职责不是照单全收，而是**追问一次**：建议一个观测门槛（前五大客户收入占比 ≤ 45%），标明这是系统建议而非用户原话，用户可直接改数值。**不做多轮对话**，避免滑向聊天产品。

无论哪种来源，观点 ID 一旦确立跨轮不变——这是差分的锚。

## 5. 研究台的渐进披露（已实现，此处备案）

| 层 | 触发 | 内容 |
|---|---|---|
| 折叠态 | — | 标题、门槛、本轮变化、结论（数字内联可点）、下一步 |
| 展开 | 点披露按钮 | 研报原话 → 原因分层（**公司已披露** 与 **仍需验证的解释** 分块，永不合并）→ 论据门禁 → 我的研判 |
| 证据侧栏 | 点任意数字 | 三层核验全过程 |

披露按钮的文案用**状态自己会引出的问题**：

- 部分支持 → 为什么不是「已验证」
- 被削弱 → 为什么判定为「被削弱」
- 待跟踪 → 缺什么才能定论
- 已验证 → 依据与论据

视觉：层级由排版与留白承担，不靠嵌套边框；颜色只花在状态上，四个降饱和色相（被削弱用陶土色而非报警红——那是研究发现，不是错误）。无玻璃拟态、无渐变、无紫色。样式作用域锁在 `.rd` 下，不污染真实管线。

## 6. 触发披露与高频处理

| 类别 | 例子 | 节奏 |
|---|---|---|
| 定期报告 | 一季报、半年报、三季报、年报 | 稳定可预期 |
| 临时公告 | 业绩预告、快报、重大合同、股东减持、监管处罚 | 高频不可预期 |

公告高频，直接沿用定期报告的触发逻辑会淹没用户。四条规则：

| 规则 | 内容 |
|---|---|
| 重要性预筛 | 先轻量匹配"是否触及已有观点的指标或命题"，不匹配则只记录不分析 |
| 去重 | 同一公告标识 + 内容哈希已处理过 → 不重复触发 |
| 同日聚合 | 同一交易日多条公告 → 合并为一次分析 |
| 静默无变化 | 目录相同且无修订 → 只写检查时间，**不建版本、不调模型** |

## 7. 用户确认

画面二产出的是**草稿**，不是状态。机器出草稿，人做最终解释。

| 操作 | 语义 |
|---|---|
| 接受 | 认可机器的事实判定与推论 |
| 改判 | 写入用户研判，与系统结论并存，**不冒充系统状态**，结转后续轮次 |
| 调门槛 | 修改核验标准 → 仅重跑受影响论据，已有文件与事实复用 |
| 排除 | 不再跟踪，历史仍可读 |

**改判与调门槛的区别**：改判是"我怎么看"，调门槛是"什么才算数"。前者不影响系统状态，后者触发重算。

确认支持**部分确认**：四档分流之后，用户可以只处理事实与强推论，把弱推论留到下一轮。

确认后事务写入：写观点修订与用户修正 → 写不可变快照 → 推进当前版本指针。历史版本不可变，写新版本不改旧版本。

## 8. 状态模型

三个维度分开存，不能压成一个枚举：

| 维度 | 值 | 回答的问题 |
|---|---|---|
| 状态 | 已验证 / 部分支持 / 被削弱 / 待跟踪 | 结论是什么 |
| 期限 | 未到期 / 进行中 / 已到期 | 核验窗口关闭了吗 |
| 阶段信号 | 高于 / 符合 / 低于 / 未知 | 在窗口内跑得怎么样 |

状态由**事实**按规则聚合得出，推论不参与聚合：

```
有核心且期限适用的反证                → 被削弱
全部关键事实成立且窗口到期             → 已验证
至少一个成立而其余未决                → 部分支持
其余                                 → 待跟踪
```

**长期因果命题的待验证，不会被短期数字自动覆盖。**

## 9. 演示剧本

### 9.1 原则

- **忠实而非虚构**：回放展示真实运行会产出的工件形态——证据切片、页码、计算值、门禁结果
- **明确标注**：常驻标注「演示回放 · 预编排，非实时模型调用」，数据标注为合成、非真实披露
- **每轮教一件事**
- **诚实失败必须出现**：拒绝计算、拒绝采信预告、拒绝管理层归因

### 9.2 四轮

| 轮 | 触发 | 证据性质 | 教什么 |
|---|---|---|---|
| T0 | 研报 + 用户手工录入一条观点 | — | 系统把宽泛表述追问成可核验门槛，并标明是系统建议 |
| T1 | **业绩预告** | 预告 | 证据性质降权：方向明确却**不产生成立的事实**，只产生推论 |
| T2 | 三季报 | 未经审计实际数 | **拒绝计算**：缺可比期 → 输出拒绝理由而非编数；另一条出现直接反证 |
| T3 | 年报 | 经审计 | **拒绝管理层归因**：数值事实成立，因果事实不成立，观点停在部分支持 |

### 9.3 每轮必须演出的瞬间

| 轮 | 瞬间 |
|---|---|
| T0 | 自建观点被追问成可核验门槛，标明系统建议 |
| T1 | 预告数字到达 → 性质判定为预告 → **不产生成立的事实** → 只生成一条克制推论 |
| T2 | 口径门禁不通过 → 拒绝计算 → 输出拒绝理由 |
| T3 | 数值事实「成立」与因果事实「不成立」**同时出现** → 观点停在部分支持 |
| T3 | 用户上一轮的改判**原样结转**，未被模型输出覆盖 |
| T3 | 一条观点标「本次未涉及 · 未被重新验证」 |

### 9.4 回放形态

时间轴驱动的预编排事件序列；可播放、暂停、逐段步进、跳到结果、调速。跑完后归档，可从研究台对应观点回看。
